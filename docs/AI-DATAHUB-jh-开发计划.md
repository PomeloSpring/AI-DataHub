## 本轮开发进展

- 语义编译补齐三跳 JOIN、HAVING、受控派生指标、嵌套聚合等结构化查询能力，并补全对应 demo 语义资产与回归用例；相关改动通过 67 项 planner 定向回归。
- 本体遍历增加按明确候选表反查图种子的能力。`prd-cn` 图当前仍缺对应映射，因此这是代码侧的能力补齐，不代表线上图数据缺口已解决。
- 手动点选分析场景现在也会在服务端复核工作空间、当前数据源与主体范围；候选列表按站点/数据源范围过滤，越界场景不回传标题。提示词回归断言同步到当前“取数前语义确认”章节标题后，范围与主体相关回归 35 项通过。
- 修正反馈 API 的 `will_be_digested` 状态：只有点踩并提供期望业务名才会生成待归纳候选；仅选择原因的反馈仍保存，但不会误报为将生成候选。新增 API 回归用例 2 项，通过。
- 语义取数新增 `semantic_plan` 与 `semantic_execute` 阶段 span，记录各阶段耗时、告警/未解析项数量和返回行数；不记录 SQL、物理表名或结果值。关联回归共 30 项通过。
- 前端 `npm run build`（TypeScript + Vite production bundle）通过；构建仍报告已有 CSS 语法、i18n 动态/静态重复导入与主 bundle 超过 500 KB 警告，未作为本轮功能阻断项处理。
- 当前阶段继续推进意图路由与反馈闭环；确定性取数快路径尚未启用。核查发现 intent gate 词典只有业务词列表，没有对象/指标/维度的结构化映射；可信执行会话在 SDK 执行阶段才领取，语义工具还要求实时工具授权与绑定校验。下一步需先定义可配置的结构化意图契约，并复用该安全执行链，再实现快路径，不能仅凭词面命中直接取数。

## 推进原则

1. 先建立可重复的评测和观测基线，再调整意图、路径和性能。
2. 权限始终由服务端角色和权限码裁决；模型输出和 AS-BOT 配置不能扩大授权。
3. 不确定的意图继续交给模型或要求澄清；快路径只覆盖能由规则可靠验证的场景。
4. 反馈先生成可审阅的候选项，不自动改写线上本体、字典或业务知识。
5. QMind 同步继续沿用当前的人工触发和审核方式；不改变既有同步策略。

## 阶段计划

### 阶段 0：冻结现状并定义验收基线

**工作项：**

- 审阅并归类当前 Qoder CLI 未提交改动，记录运行时版本、安装路径、凭据来源和升级/回退方式。
- 按真实用户问题整理一版最小评测集，覆盖：准确命中、歧义、无业务实体、追问、多轮上下文、系统能力、权限拒绝、附件和异常降级。
- 记录当前成功率、误拦截、意图判定耗时、完整回答耗时、模型调用次数、队列等待、失败类型及反馈关联率。
- 为每个任务指定业务验收人和可接受阈值。性能改善目标依据基线确定，不先填未经测量的数字。

**交付物：**评测用例清单、性能基线记录、Qoder 运行时核对清单、任务验收矩阵。

**退出条件：**每个任务都有可观察的验收标准；评测基线可重复运行；未提交运行时改动有明确保留或回退决定。

### 阶段 1：完成意图路由、快路径与评测反馈闭环

**对应任务：**AS-BOT 意图识别和路径规划、意图识别路径优化、eval 评测集和反馈机制。

**工作项：**

- 将现有意图闸门、语义 planner 和反馈原因映射到同一评测分类中，补齐误拦截、漏拦截和歧义样本。
- 先在 shadow 模式比较路由结果与真实模型路径，再逐步启用 enforce；判定异常继续 fail-open。
- 根据评测结果实现有限的确定性快路径，首批只处理稳定、权限明确、结果可核对的请求；其他请求维持现有模型与语义层流程。
- 确保评测结果按层、按场景和版本落库；基线门禁同时检查绝对质量和相对回退。
- 确保点赞/点踩与 trace 关联；负反馈归纳为候选项后由人工审核，再进入回归评测。

**退出条件：**新增快路径用例全通过；整体评测未低于已确认基线；误拦截样本可追溯；负反馈可以追到候选、审核和复测结果。

### 阶段 2：加固角色继承、系统能力和执行层/Qoder Agent

**对应任务：**AS-BOT 权限控制（继承角色）、AS-BOT 系统能力支持、执行层开发、Qoder agent 功能开发。

**工作项：**

- 覆盖角色权限授予、拒绝、只读/写入级别、敏感权限收窄、AS-BOT 关闭能力、角色变更和缓存失效等正反向场景。
- 核实系统能力和业务能力按权限叠加；未授权能力应显示清晰原因，不能因缺配置静默注册或绕过工具策略。
- 审核 Qoder SDK/CLI 的安装、版本固定、凭据隔离、工具注入、超时、取消、退出码和失败提示；完成现有本地改动的代码审阅后再纳入版本控制。
- 检查管理页面保存配置后，运行时缓存和会话权限能在预期窗口内更新。

**退出条件：**关键越权路径均有回归用例；角色变更后行为符合设定；Qoder 可从干净环境按文档安装、启动、执行工具并安全失败。

### 阶段 3：用可观测数据驱动 AS-BOT 性能优化

**对应任务：**AS-BOT 性能优化、应用可观测。

**工作项：**

- 补齐从请求入口、意图判断、检索、工具调用、语义规划到模型输出的阶段耗时与失败原因。
- 用固定问题集和约定并发量测量 p50/p95 延迟、队列等待、缓存命中、模型调用次数、错误率及资源用量。
- 先定位最慢阶段，再逐项调整缓存、检索预算、并发和重试策略；每次变更重复同一基准测试。
- 在管理端提供按时间、模型、用户/角色、处理阶段和反馈结果筛选的诊断视图；明确采集关闭或缺表时的状态。

**退出条件：**完整请求链路可定位主要耗时和失败；相对阶段 0 的关键延迟有实测改善；错误率、权限拒绝和回答质量没有回退。

### 阶段 4：完成 QMind 业务知识库试点

**对应任务：**QMind 业务知识库构建（`xingyu+junheng`）。

**工作项：**

- 先选一个业务流程作为试点，梳理数据源、加工/同步步骤、指标口径、产出文档、操作角色和异常处理。
- 将本体、指标/维度说明、经审核的业务文档和操作流程组合成可维护的知识内容；标注来源、负责人、版本和适用范围。
- 复用现有脱敏渲染、Notebook 导入、知识库绑定和检索链路；通过人工审核与同步水位确认更新结果。
- 用真实业务问题检查检索命中、引用准确性、旧版本处理和权限边界；试点通过后再扩展到其他业务流程。

**退出条件：**试点流程文档有明确业务负责人；代表性问题能检索到正确、当前且可追溯的依据；同步状态和失败可见；无物理敏感信息外泄。

### 阶段 5：回归验收与发布

- 对照阶段 0 的评测、性能和权限基线重复验证。
- 核对所有新增用例、运行时配置、QMind 文档版本和可观测指标。
- 更新操作文档、故障处理和回退步骤；确认未提交文件、迁移和部署改动归属。
- 逐项记录通过、未通过和待业务确认项，再决定是否发布。

## 建议顺序

`阶段 0 → 阶段 1 → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5`

阶段 1 与阶段 2 的自动化用例可以并行补充；阶段 3 的性能调优依赖阶段 0 的基线和可观测数据；阶段 4 可独立准备业务材料，但应在试点范围和负责人确认后开始正式同步。

## 完成定义

每个任务需同时满足：对应功能在真实入口可用；关键成功、拒绝、异常路径有自动化覆盖；质量、权限或性能指标达到阶段 0 确认的门槛；必要的业务文档和操作说明已更新。仅有模块、页面或接口存在，不单独视为完成。
