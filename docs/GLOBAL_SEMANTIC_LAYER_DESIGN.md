## 2. 目标 / 非目标

**目标（v0.4 终态：人编业务知识图谱）**
1. **本体 = 人工编辑的企业业务知识图谱**（对象/属性业务名/口径/别名/关系——企业业务语义）；**无 datasource_id、无物理表/列名、无"选数据源生成模型"**；
2. 部署绑定（object × 站点 × 物理表/列映射）是**独立机械配置层**（where），工具辅助生成/校验、不属于本体——"完全由人编辑"指业务语义层；
3. 部署派生清单（≥2 站对象）作为 **LLM 编排知识**（§6）；跨站由 LLM 逐站编排，语义层只做单站 SQL 编译（v0.5 修正）；
4. LLM 通过知识/技能获知站点↔数据源拓扑与跨站操作方法（知识图谱只检索一次结构）；
5. **用户权限 = 数据源作用域**：作答在授权范围内自然收窄（静默）；执行失败与权限裁剪严格分离。

**非目标**
- 不做跨源 UNION ALL / 联邦执行改造（§8 仅评估演进条件）；
- 不做全球去重口径（同名用户五站去重——不可确定性编译，回抛提示不给假数）；
- 不引入第四种 kind（见 §4）；
- 不改 canonical doc 编辑路径与级联主链路语义（只收敛其作用域，已落地）；
- **不做权限提示/缺站提示**（用户明确裁掉：静默作用域，见 §10）；
- **不做纯手敲物理列映射**（错数风险，宁缺勿错）——人编业务语义，工具管物理映射（§3 边界声明）。

## 3. 三层信息架构（what / where / how）—— 人编业务知识图谱为核心

```
人编业务知识图谱（what，核心）—— 唯一本体，人类编辑
  案例、订单、用户、公司…：对象 + 属性业务名 + 口径 + 别名 + 关系
  canonical doc（JSON）= 单一可编辑源；**无 datasource_id、无物理表/列名**
  → Oxigraph 企业业务知识图谱（IRI 总线，SPARQL 关系查询，节点全局唯一）
        │
        │ × 部署绑定（where，机械配置层）—— **不属于本体**
        │   object_key × 站点 × 物理表 + 列映射（业务名→物理列）；工具辅助生成/校验
        │   ├─ 中国站(prd-cn) / 国际站(prd-en) / 欧洲站(prd-eu) / 英国站(prd-uk) / 日本站(prd-jp)
        │
        │ × 操作知识（how，知识库/数据分析 skill）—— 不是本体对象
        │   站点↔数据源拓扑、跨站查询方法（scope/站点维度）、口径红线
        │   由 LLM 检索/技能读取，指导"怎么操作"，可随实践演进而无需建模审批
        ▼
查询时：检索 1 次（知识图谱结构）+ 读操作知识 → 逐站受治理执行 N 次（权限静默收窄）→ 服务端合并
```

**为什么站点/数据源不建模为本体对象**（v0.3 核心决策）：

| # | 理由 |
|---|---|
| 1 | 站点是**部署形态**不是业务实体——业务主体（案例/订单/用户）才是建模对象，站点只是它们的部署位置 |
| 2 | 跨站能力已从**部署绑定**派生（§6），不需要站点对象参与；绑定表本身就是站点↔源的事实 |
| 3 | "怎么查全球"是**操作方法**，适合 skill/知识库（可演进、无需建模审批、不占本体图谱） |
| 4 | 权限按数据源裁决（§10），不需要站点本体参与鉴权 |

**原多站点语义网（site_*/ds_* 本体对象）的去留（✅ Q8 已拍板：一次性退役）**：退场为知识/技能内容（route/pc_* 机制同步收缩），B5 批次一次性完成（绑定表已是事实源，无兼容包袱）。显式 pc_* 口径红线改由**服务端结果提示 + skill/规则**双重承载（不依赖 LLM 自觉）。

**源本体退役（v0.4 核心决策）**（✅ Q10 已拍板：kind 收缩 system/business，规则文本修订随 B6 落地并展示 diff）

| 现有机制 | 终态 |
|---|---|
| `kind='source'` 源本体模型 | **退役**；kind 收缩 system/business（触碰 `as-bot-system-waker.md` 域判别规则文本，修订需单独确认） |
| doc `objects[].execution_binding`（product_ref/物理表/column_map） | **移出本体 doc** → 部署绑定层；doc 变纯业务语义（5W2H 槽位） |
| "选择数据源生成本体模型"（生成任务/同步生成） | **退役** → 降级为"部署绑定引导"（从表元数据辅助生成绑定，非建模流程） |
| binding_resolver 归属裁决（按 model.kind） | 改按**部署绑定层**裁决（object_key × 数据源），与模型归属解耦 |
| 图谱按数据源命名图分区（`ds:{id}`） | 收缩为业务/系统域图（✅ Q12 已拍板：二分） |

**"完全由人来编辑"的边界（诚实声明）**：人编的是**业务语义**（对象/属性业务名/口径/别名/关系）；**物理列映射不让手敲**（17 对象 × 5 站 × 列映射 = 错数风险，宁缺勿错）——工具对着表元数据生成/校验，人工只审业务层。初始化成本：现有 doc 的业务字段可"降级迁移"为人工起点，不从零手敲。

**过渡态声明**：现状契约模型（`kind='source'`、`datasource_id=prd-cn`）是过渡载体；v0.4 终态下"契约"概念并入业务知识图谱 + 部署绑定层，不再有带数据源的模型。

## 6. 跨站能力：部署即编排知识（v0.5 修正）

**派生规则**：对象在 ≥2 站有部署绑定 ⇒ 列入跨站清单。部署绑定表是**唯一事实源**（5 站 × 17 对象已就绪）——新站上线、绑定一建，清单自动出现。（图 deployed_at 边不是依据，站点对象退场后仅绑定表是事实。）

**清单是给 LLM 编排用的知识，不是服务端触发器（v0.5 修正）**：跨站由 **LLM 逐站编排**（对每个授权站点各发一次 `run_semantic_query`，见 §7/§8），派生清单通过 `get_metrics.deployments` + skill 告诉 LLM "该对象在哪几站可查"。

**显式 `pc_*` 本体对象彻底退役（✅ Q3 + v0.5 修订）**：不保留别名入口；其内容（"跨站案例/跨站订单"的用法）**作为示例写进数据分析 skill**；官网询盘红线由**服务端结果提示（机械注入）+ skill/规则**双重承载。操作知识落点（✅ Q9）= 更新现有数据分析 skill（`backend/modules/mind/config/skills/data-analysis/SKILL.md`，Qoder 规范 SKILL.md；已落：编排步骤/站点↔源映射/授权清单/红线/示例写入「取数与治理」节），不新增 skill。（v0.5 附注：旧 agent 目录 `config/agents/`、孤儿 `agent_loader.py`、旧规范 `skills/nl2sql/`（无绑定）已清理，技能体系只剩 SKILL.md 规范。）

**派生清单输出形态**（get_metrics.deployments）：

```json
{"object": "用户", "aliases": ["user", "客户"],
 "deployments": [{"site": "中国站", "datasource": "prd-cn"},
                  {"site": "国际站", "datasource": "prd-en"}, "...",
                  {"site": "日本站", "datasource": "prd-jp"}],
 "cross_site": true}
```

## 7. 意图契约（v0.5 修正）：业务 SQL 维度 + 数据源寻址

**SemanticQuery 只管业务 SQL**：object/metrics/dimensions/filters/order/limit/time_* —— 这些确定性编译进 SQL；**站点不是 SQL 维度**，全球性是编排问题不是意图字段。

```json
{"object": "用户", "metrics": ["用户数"], "dimensions": ["注册渠道"], "time_window": "3M",
 "datasource": "prd-en"}        // 目标数据源（name，可选；缺省=会话数据源）
```

| 问法 | 意图形态 | 编排 |
|---|---|---|
| "全球有多少用户" | 对每个**授权站点**各发一次 `{object:"用户", metrics:["用户数"], datasource:"<站点源名>"}` | **LLM 编排**（站点↔源映射来自 skill；授权站点清单来自 list_datasources） |
| "各站点用户数" | 同上 + 汇总表 | LLM 汇总（口径提示：合计≠去重） |
| "中国站用户数" | `{..., datasource:"prd-cn"}` 单次 | 单站 |

**契约边界（v0.5 修正 v0.4）**：
- ~~`scope:"all_sites"`~~ **取消**—— v0.4 曾设 scope 字段+服务端展开，是设计错误（站点职责归 LLM 编排）；
- 意图带「站点」维度 → **拒收回抛引导**（"站点对比请按站点编排多次查询"），站点维度不进 SQL；
- `datasource`（名）服务端按授权集解析：未命中回抛候选名（不猜，与 execute_sql 同纪律）；无权 → 拒绝（fail-closed，Q5）；
- 单站失败 → 该次调用显式错误/`degraded`（Q7 轻描"部分站点暂无数据"）；权限裁剪**静默**（不提缺站/无权限，§10）。

**随之退役**：服务端自动跨站展开（`cross_site.maybe_execute_cross_site`/反向提升/promoted_from）——已落地代码列为 B1 退役项。残余风险：LLM 漏站/忘循环 → 由 eval trace 用例盯轨迹（§15）；若漏站率高再评估把 loop 下沉为服务端工具（演进选项）。

## 8. 执行形态（v0.5 修正）：LLM 逐站编排 + 服务端单站受治理执行

跨站 = LLM 编排 N 次 `run_semantic_query`（各带 `datasource` 名），每次都是**完整受治理单站执行**（RLS/RBAC/敏感基线按该站策略）；服务端不做跨站展开/合并（无 UNION、无服务端合并、无合计行——LLM 汇总时带口径提示）。也不用一条 UNION ALL，理由：

| 维度 | 逐站 N 条（选定） | 一条 UNION ALL |
|---|---|---|
| 物理现实 | 五地独立 RDS 实例，各走各的连接 | 跨实例需联邦执行（DataFusion），链路长 |
| 治理粒度 | 每站独立过 `execute_query_with_permission`（RLS/RBAC/敏感基线按该站策略），授权逐站裁决 | 联合裁决语义无法表达（一源无权整句拒？拆段？违反 fail-closed） |
| 故障隔离 | 单站失败/未授权不影响其余站（LLM 编排跳过，权限静默、失败可诊断，§10） | 一条挂全挂 |
| 口径可诊断 | 站点列 + 逐站独立口径（红线：不混同跨国口径） | 站点来源/口径差异被抹平 |

**边界**：单站内多对象 JOIN 仍编译进**单条 SQL**（planner）；拆分只发生在跨数据源之间，且由 LLM 编排（v0.5）。与执行引擎路由一致（单源不走 DataFusion，跨源才联邦）。

**联邦演进条件**（若将来要 UNION ALL/库侧 SUM 合计）：① 跨源语句授权联合裁决语义；② RLS 注入对 UNION 各段逐段改写覆盖；③ 审计一句 vs N 条定口径。另：若 LLM 编排漏站率高，备选演进是把逐站 loop 下沉为服务端工具（折中），由 eval trace 数据决定。

**合计行（v0.5 修订 Q4）**：服务端合计行**取消**（无服务端合并）；LLM 汇总各站结果时自行加总并标注"各站合计≠去重全球数"（skill 知识）。

## 9. LLM 感知面 **[计划]**

LLM 的世界模型包含：**站点↔数据源关系 + 对象跨站能力 + 怎么查全球**，载体是**知识库/数据分析 skill**（不是本体对象），业务本体只检索一次结构：

| 感知项 | 载体（v0.3：知识/技能化） | 边界（护栏 §7 黑盒） |
|---|---|---|
| 站点↔数据源 name 映射（"中国站=prd-cn"） | 现有数据分析 skill（`skills/data-analysis/SKILL.md`）/知识库；get_metrics.deployments[].datasource（name，目录事实） | 数据源 **name 可见**（与 list_datasources 同口径），**id/连接信息永不出** |
| 跨站编排方法（逐站 run_semantic_query + 汇总口径 + **示例**（原 pc_case/pc_order 场景）） | **现有数据分析 skill**（`skills/data-analysis/SKILL.md` 更新，不新增） | — |
| 契约结构（对象/口径/别名/关系） | knowledge_search / get_metrics / relations（Oxigraph 契约图，节点全局唯一） | 物理 join 表达式/物理列不出 |
| 口径红线 | 服务端结果提示（机械注入）+ 知识库/规则 | — |

**职责三分（v0.5 澄清：谁提供什么，避免多余调用与重复登记）**：

| 信息 | 载体 | 性质 |
|---|---|---|
| 站点↔数据源映射、编排方法、口径红线、示例 | **skill system.md**（静态知识） | 偶尔更新（新站才变）；不堆动态事实防漂移 |
| 用户可查数据源（授权集） | **`list_datasources`**（已有工具） | 逐用户动态，必须运行时取（不进提示词：安全+时效） |
| 对象×站点部署清单 | `get_metrics` **顺风车字段**（deployments，非独立一步） | 事实源=部署绑定；可砍选项见 Q14（砍后靠"未绑定"报错自纠） |

执行寻址**不需要** LLM 传数据源 id：目标源用 `datasource`（名）表达，服务端按授权集解析（与"工具入参禁 datasource_id"纪律一致）。LLM 只看到**授权站点清单**（list_datasources 授权集内 name），自然静默收窄（§10）；对用户不提权限/缺站。编排清单 = list_datasources（能查哪几站）∩ deployments（对象在哪几站有）。

## 10. 权限与失败语义

**权限 = 数据源作用域（v0.3 用户拍板）[计划]**
- 未授权站点**静默裁剪**：不输出"还有其他站点/你没有权限"类提示；作答在授权范围内完整给出（对用户而言这就是"他的全球"）；
- 与 RBAC 行过滤同构：问总数不提示"还有别人的数据"——权限裁剪是**作用域定义**，不是功能失败；
- **与 no-silent-degradation 的边界**：该规则禁止掩盖**功能失败**；权限裁剪不是失败（不触发降级标注义务）。**执行失败**（有权限但查挂）不得冒充完整数据——结果标 `degraded` + 服务端日志可诊断 + LLM 轻描"部分站点暂无数据"（✅ Q7 已拍板）；
- 显式问无权站（"中国站数据量"且无权）→ **拒绝**（fail-closed：显式请求越权对象 ≠ 全球性问题）（✅ Q5 已拍板）；
- 每站数据出来后过该站 RLS/RBAC/敏感基线（不变）；
- 服务端审计留全量痕迹（sites_skipped 进 metadata/审计，仅不进对外叙事）。

**[已落地]**（现状，将按上述语义调整）：逐站鉴权走 `role_service.get_user_allowed_datasources`（角色唯一裁决点）；跳过原因区分 SemanticError 业务级消息与通用异常（只进日志）。

## 11. 口径红线（跨站结果必带）

1. 各站独立口径，**不混同跨国口径**；
2. 各站合计 ≠ 去重全球数（同名用户五站可能重复登记）——问去重口径时回抛提示，不给假数；
3. 官网询盘仅中国站可查，**禁五站相加**（服务端机械提示 + 知识库双重承载）；
4. 权限裁剪静默（作用域，不作口径提示）；**执行失败不得冒充完整**（degraded 标注）；
5. 措辞按用户视角（"数据量：X"），权限场景不用"仅/缺少/无权限"字眼。

## 16. 验收标准

1. "全球有多少用户"（全授权）：LLM 逐站编排（每个授权站点各一次单站调用）+ 汇总 + 口径提示，无手工 pc_* 参与；
2. "全球有多少用户"（仅新加坡权限）：只对授权站发起调用，直接答数据量，**回答中无"其他站点/无权限/仅"等提示**（need-to-know 静默作用域）；
3. "各站点用户数"：LLM 逐站编排 + 汇总带"合计≠去重"口径提示；意图带「站点」维度 → 拒收引导（不进 SQL）；
4. "中国站用户数"：单站常规不误触发；显式问无权站 → 拒绝（fail-closed）；
5. 执行失败站：标 degraded 不冒充完整（叙述按 Q7）；权限裁剪不进对外叙事，审计留痕；
6. 本体管理页：业务主体为核心 + 部署绑定子页；站点/数据源以知识/skill 呈现；
7. LLM 轨迹零 test-alb/裸 id；数据源仅 name 可见；
8. eval 总/分 tag 正确率不低于改前；护城河三件套全绿。
