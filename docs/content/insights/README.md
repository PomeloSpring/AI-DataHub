## 目录与文件

```
docs/content/insights/
├── README.md          本文件
├── manifest.json      栏目 + 文章清单 + 标签词表（seed 脚本唯一输入，由脚本自动生成）
├── tags.json          受控标签词表 + 命中数 + 侧栏展示规则
└── <栏目>/<slug>.md   正文（front-matter 为唯一元数据来源）
```

`manifest.json` / `tags.json` 是**生成物**，不要手改；改正文 front-matter 后重跑生成脚本即可。

## front-matter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `slug` | 是 | 对外 URL 标识，全局唯一，小写字母与连字符 |
| `title` | 是 | 列表与详情页标题 |
| `category` | 是 | 栏目 `category_key`，必须存在于 `manifest.json.categories`（悬空即校验失败） |
| `summary` | 是 | 列表卡片摘要，≤ 120 字，不重复标题 |
| `tags` | 是 | 2—4 个，**必须取自 `tags.json.vocabulary`** |
| `kind` | 是 | `markdown` / `link` / `file` / `promoted` |
| `author` | 是 | 署名的业务主体（部门/团队名），不写个人账号 |
| `published` | 是 | `false` = 草稿，不入库为可见内容 |
| `pinned` / `featured` | 否 | 置顶 / 进精选大卡区；首批精选控制在 5 篇以内 |
| `published_at` | 是 | ISO 日期，列表按此倒序 |
| `review_by` | 是 | **复审到期日**。含外部市场数字或法规条款的文章必填（这类内容会过期） |
| `references` | 是 | 引用清单。本批每篇都有，无出处的数字不得写进正文 |

## 标签纪律（本批踩过的坑，已固化成规则）

首批 10 篇最初产出了 26 个标签，其中 21 个只命中 1 篇——侧栏「热门标签」会全是点开只有一个结果的孤儿标签，筛选形同虚设。收敛后确立三条规则：

1. **标签必须取自受控词表**（`tags.json.vocabulary`，当前 14 个），不允许自由输入；
2. **侧栏标签云只渲染命中 ≥2 篇的标签**；命中 1 篇的标签仍在文章页与筛选中生效，只是不进云；
3. **禁止用宽泛标签凑数**。校验时发现「质量控制」被自动补到 4 篇文章上变成万能标签——已改为按各篇实际命中的主题标注。

文章数增长后（≥20 篇）再考虑扩词表，而不是先扩词表再等文章。

## 数据占位约定（两种标记不要混用）

三类标注，缺一不可：

1. **`【待填：…】`** —— 只有本公司才有的数据、且**还没拿到真实值**时的半成品标记。
   服务端门禁按正文里的 `【待填` 硬拦（提交审核与发布两条路都拦），带它的稿子不得发布；
   填不出来就把整段删掉，或改成第 4 条的「不代列」写法，**不留假数**。
2. **`（来源：…）/ references`** —— 外部公开数据必须写明出处与年份。
3. **`（示例值，仅示意口径）`** —— 只允许出现在"教你怎么算"的模板段落，且必须紧邻口径说明。
4. **`「由 X 部门维护，本文不代列」`** —— 数据确实拿不到、但该处删掉会伤文脉时的成品写法：
   读者知道找谁要，也不会把虚构数字当成公司结论。
5. **`【由X填写：…】`** —— **模板类文章的填写位**（如发布说明模板），是成品特征而非半成品标记，
   与 `【待填：…】` 刻意不同字，门禁不拦；正文必须同时写明"填实前不得对外发布"。

## 正文格式约定（校验脚本会拦）

1. **标题唯一事实源 = front-matter 的 `title`**，正文**不得**再写 H1。
   首批成稿时正文都带了一个 H1，其中 6 篇与 `title` 文字不一致（我写了缩短版）——
   详情页会用 `title` 渲染 `<h1>`，两处并存就是双标题，且必然漂移。已全部移除。
2. **小节从 `##` 起**，详情页右侧「目录」由 `##`/`###` 自动生成，不手工维护锚点。
3. 代码围栏必须成对；表格每行竖线数一致。
4. 校验规则已写进 `manifest.json.content_rules`，seed 脚本导入前应逐条断言，**不通过就报错，不得静默跳过**。
