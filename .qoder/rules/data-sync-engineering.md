# 数据工程域（同步 / DAG / 物化）：AI 零接入 + 独立执行围栏 — 强制规范

> 本域冲突反复出现：同步与物化既被按"取数"套用分析面规则（默认 `LIMIT`、调用者 RLS、结果侧脱敏），
> 又在权限配置里被当成 AI 可写动作（`sync:manage`/`sync:execute` 配 `ai_access='write'`）却**没有任何消费方**
> ——角色页勾了不生效，属"配了没用"的空承诺。以下是本域的收敛规则，
> 新增/改动数据同步、DAG、UDF、定时物化、执行体接入前必读。

## 1. 域定位：数据工程是"建可信数据"，不是"回答用户问题"
- **两条通道，围栏不同**：数据面（读源表 → 计算 → 写授权表，**不向人或 LLM 返回数据行**）与分析面（向人/LLM 返回数据行）。
  判定归属只看这一条问题：**结果是否作为数据行交给人或 LLM**。
- 护栏 §1「全平台唯一取数执行口」**约束的是分析面**。数据工程通道不借用分析面语义（不补默认 `LIMIT`、不注入调用者 RLS、不走结果侧脱敏），
  也**不得**借用分析面的"合规外衣"绕开本域围栏——严禁把 `require_limit=False` 当批处理旁路开关。
- 写目标沿用既有边界声明（`modules/flow/dag/target_writer.py`）：不返回数据行、不经 LLM、凭据只在服务端。

## 2. AI 零接入：本域不展示、不调用、不裁决
- 权限点 `sync:read` / `sync:manage` / `sync:execute` / `sync-logs:read` / `dag:read` / `dag:manage` / `udf:*`
  的 `adh_perm_registry.ai_access` **必须为 `none`**、`ai_action_key` **必须为空**。
- **代码层硬上界**：上述权限码**须**纳入 `perm_link.SECRET_BOUND_NONE_PERMS`（与涉密域同一机制），
  管理员误配成 `write` 也不生成工具、不通过裁决——配置不可覆盖，防未来迁移把口子重新打开。**仅写库不够**：没进这道 cap，下一批迁移或另一个环境的配置就能把口子抬回去。
- 四个"不得"（缺一即违规）：
  1. **不登记功能工具**：不得进 `function_tools.FUNCTION_ACTION_SPECS`；
  2. **不作为任何 AI 动作的裁决码**：`as-bot-system-waker §3` / `fde-evolution §2` 的动作→权限码映射里**不得再出现** `metadata.sync`→`sync:manage` 这类条目；
  3. **不进提示词与 skills**：不得向模型广告"可创建/触发/查询同步任务"（`prompt_composer`、`data-analysis/SKILL.md` 均不得出现本域入口）；
  4. **不在 AI 可见清单**：工具时间线、AS-BOT 能力清单、`/roles/current/permissions` 下发的 menus 不得出现同步/物化入口。
- 菜单照常登记（`menu-permission-sync` 不变）：`ai_access='none'` 是**显式标注**（`ai_note` 写明"数据工程属运维动作，不开放给 AI"），
  不是缺省留空——缺省会让后人以为"忘了配"。

## 3. 元数据同步 ≠ 数据同步（不得共用权限点）
- schema 发现/字典同步属 **catalog 治理域**；数据搬运/聚合属**数据工程域**。两者今天共用 `sync:manage` 就是碰撞点：
  一旦为前者开放 AI，就顺带把数据搬运开放给了 AI。
- 若未来确需让 AI 触发元数据同步：**另立权限点**（如 `metadata:sync`，挂语义建模/资产菜单），单独决策 `ai_access`；
  **不得**复用 `sync:manage`，也不得把任何数据搬运动作映射到元数据码上。

## 4. 数据工程通道的七条围栏（缺一不可；缺则该功能视为未开放）
1. **登记制白名单**：源（数据源 + 表）与目标（库 + 表 + 分区）必须在任务/契约配置中显式登记；未登记的表一律拒；
2. **凭据服务端解析**：只接受数据源**业务名**，凭据由 `get_datasource_conn` 运行时解析；不落代码、不落配置正文、不落日志、不进 LLM 视野（护栏 §7）；
3. **执行计划由平台编译**：待执行 SQL 与血缘输入由服务层生成（含按引擎方言取正文），执行体不得自造 SQL 来源；计划回传供血缘与口径记账；
4. **预算即拒**：预估扫描量 / 超时 / 单批行上限 / 并发度显式配置，超预算**拒绝并给原因**——严禁"补个 LIMIT 继续跑"的静默截断（这是错数不是降级）；
5. **回报必复核**：执行体回报的行数与"成功"**不作权威依据**；平台侧对目标表 `COUNT`/分区可见性/校验和对账后才标记就绪（防谎报成功）；
6. **原子切换**：覆盖写必须 staging 分区 → 交换或版本切换，失败不留半态；分区级幂等以业务日期为键可重跑（含回填）；
7. **通道显式**：审计与运行实例落 `channel=data_engineering`、契约/任务 id、口径版本、分区与对账结果，与用户查询审计分列（护栏 §9），监控页可区分。

## 5. 敏感与权限口径（物化/数仓层）
- `block` 列 = **编译期拒绝进入物化**（不是结果侧剔除）；`mask` 列 = 数仓**存原值**，脱敏继续在**读侧编译期**注入（护栏 §7 同口径），
  使"改脱敏配置不需重刷历史分区"。
- ETL 产出**不得**因任务 owner 的行权限而改变（行级隔离不是数据质量的定义权）；消费侧读取时按查询者再施加 RLS（mart 须保留判定列），
  或只落聚合层以规避行级差异。
- **平台是权限唯一裁决点**：数仓侧只持少量服务账号（ETL 写账号 / 只读查询账号 / Catalog 只读账号），
  **不得**把平台角色映射进数仓 RBAC（两套权限必然漂移，属最难排查的事故类型）。

## 6. 执行体外移的交接契约（控制面唯一 + 数据面可插拔）
- 控制面（平台）独占：调度与依赖、幂等与租约、权限裁决、凭据保管、口径版本、血缘与数据产品登记、运行监控、**成功判定**。
- 交接只有一对契约：`ExecutionPlan`（下发）与 `RunReport`（回报）。三形态执行体——引擎下推（默认）/ 分片算子（SLS、ES）/ 外部脚本（兜底）——
  吃同一份计划、回同一份报告；契约不得为某一种执行体特化。
- 外部执行体不得持有凭据库、不得自造 run 幂等键、不得直接向终端用户回数据行；若必须短期下发凭据，须带 TTL + 按 run 授权 + 仅限登记目标。
- 兜底才考虑外部脚本；开放通用 Python/Shell 节点前必须先证明声明式算子表达不出来（否则血缘、口径版本、可复现性三者同时失守）。

## 7. 落地与回归门禁
- 规则改动**同批落地**：幂等迁移（把 `sync:*`/`dag:*`/`udf:*` 的 `ai_access` 钉为 `none` 并写 `ai_note` 原因）→ **应用到当前库**并核验；
  `perm_link.SECRET_BOUND_NONE_PERMS` 同步增项；角色页对"配置无消费方"的项如实标注（`perm_link.ai_channel`）。
- 必跑用例：
  - `tests/test_function_ai_access.py`：sync/dag/udf 系有效级别必为 `none`，且不得出现在 `PERM_GATED_ACTION_PERMS`；
  - `tests/test_dag_engine.py`：节点失败必显式 `failed`/`partial`、无假成功、错误脱敏；
  - 触碰执行口/写入通道时另跑护城河三件套（护栏 §11）。
- 本域新功能验收判据**必须包含**两条：① 落地行数与源侧对账相等；② 未登记的源/表被显式拒绝。"跑通了"不算验收。

## 10. 与相邻规则的关系
- 取数口与审计基线：`security-guardrails.md` §1（本域边界已在该节 §1 末条声明）、§5（`LIMIT` 语义划界）、§9（审计分列）、§12（反模式）。
- 失败不得静默掩盖：`no-silent-degradation.md`（本域的“预算即拒 / 回报必复核 / 半态不得当成功”是它在数据面的具体形态）。
- 菜单与权限点登记：`menu-permission-sync.md`（本域菜单照旧登记，`ai_access='none'` 是显式标注）。
- AI 动作域边界：`as-bot-system-waker.md` §3/§5、`fde-evolution.md` §2（均不得引用本域权限码）。
- 冲突时以**更严**的一侧为准：若某动作既属数据面又向用户回数据行（如“物化前预览样行”），按分析面围栏执行，不得拿本域围栏放宽。

## 11. 反模式速查
- ❌ `sync:*`/`dag:*` 配 `ai_access='write'`/`'read'` 却无工具、无裁决点（空头承诺，角色页勾了没效果）；
- ❌ 把 AI 动作映射到数据同步权限点上（元数据同步蹭 `sync:manage`）；
- ❌ 批处理沿用交互式默认 `LIMIT` 并据此报成功（静默截断 → 错数）；
- ❌ 以执行体回报行数直接标记分区就绪；
- ❌ 用 `TRUNCATE + INSERT` 充当 overwrite（读侧有空窗）；
- ❌ 数仓里存脱敏后的值（改一次脱敏配置要重刷全部历史）；
- ❌ 把平台角色映射进数仓 RBAC，或在脚本里硬写连接串/账号；
- ❌ 在提示词、skills 或 AS-BOT 工具清单里出现"创建/触发同步任务"的能力广告。
