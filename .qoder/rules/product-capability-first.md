# 功能与数据必须走项目自身能力（禁止刷数脚本代跑）— 强制规范

> 能证明"项目做对了"的只有项目自己的入口。用脚本把结果直接塞进库，表里看着齐全，
> 但权限码、字段校验、级联派生、审计脱敏、UI 渲染全都没被走过一遍——上线后用户点不动、
> 图谱/KB 还是旧口径、口径算错才发现，代价是被掩盖的缺陷一次性集中暴露。
> 刷数脚本不是捷径，是把验证成本推迟到交付之后。

## 1. 适用范围与判定

判定两问，任一为"是"就必须走 §2 的产品路径：

1. 这个产物是不是项目本身要交付/展示给用户的功能或数据（本体对象、指标、维度、绑定、看板、图表、数据集、
   文章、知识库文档、权限码、菜单、数据源、站点、任务…）？
2. 这件事产品界面/接口做不做得到？**做得到 → 必须走产品路径**；做不到 → 那是能力缺口（缺陷或需求），
   按 §4 报备，**不得用脚本顶替**然后宣称功能已完成。

判据只有一条：**产物必须是产品路径产生的，不是"库里恰巧有一行"**。

## 2. 唯一可采信路径（本项目的"原本能力"）

| 域 | 产品入口（唯一可采信） |
|---|---|
| 本体对象 / 站点白名单 | 编辑 canonical doc → `save_draft` → `publish`（activate）级联（ontology-modeling §1/§6） |
| 指标 / 维度 / 字典 | 字典写入口（`bound_object_key`、formula、`target_column` 校验在此发生） |
| 看板 / 图表 / 数据集 | 既有 REST（权限码裁决 + 字段校验 + 快照/digest + 血缘） |
| 权限码 / 菜单 / 角色授权 | 幂等迁移 SQL（`docker/mysql/*.sql`）+ 应用到库核验（menu-permission-sync §4）——结构性真源，不属刷数 |
| 数据源 / 站点登记 | 服务层登记入口（如 `register_*` 走 `get_datasource_conn`，凭据不进 SQL） |
| 内容中心 / 知识库 | 既有写入口（leak 扫描 + 乐观锁 + 版本戳） |
| 评测种子 / 内容播种 | 既有写入口或服务层函数，不裸 `INSERT` 造行 |

`backend/scripts` 里的 ② 类运维脚本（script-hygiene §1）**允许存在，但只做编排与调用**：
循环调接口、批量重放、巡检对账——不得自己拼 `INSERT/UPDATE/DELETE` 去绕过服务层。

## 3. 刷数脚本为什么不算验证（必被绕过的四件事）

1. **权限码裁决**：`api_permission` 中间件 / `require_write_perm` 从未执行 → 上线后 403，或"角色页能勾、接口不认"；
2. **字段与形状校验**：孤儿引用阻断、enum 合法性、`chart_type` 必须真实存在、`_reject_destructive_overwrite` → 数据形状非法也能落库；
3. **级联派生**：对象 → bindings → 图谱 → KB、发布 → 旧快照失效、同步 → 水位线 → digest 校验 → 全是半截状态；
4. **审计与脱敏**：审计行缺失、mask/RLS 编译路径没走过 → 改一次配置要重刷全部历史。

典型后果：直写 `adh_ontology_objects` 造对象 → 图谱/KB 仍是旧口径、activate 校验从没跑过；
直插看板配置 → 面板打开 403 或渲染空白；直写 `adh_metrics` 公式 → 语义编译报错或静默算错。
"脚本跑通了、表里有数据"属于**假成功**（no-silent-degradation）。

## 4. 允许的例外（三条，且必须显式声明）

1. **结构性/配置性真源**：schema、枚举、权限码与菜单登记 → 幂等迁移 SQL（script-hygiene §2），这本就是产品口径；
2. **凭据类登记**：凭据不能进迁移 SQL，走 `register_*` 运维脚本，但脚本内部仍调服务层（`get_datasource_conn`），不裸拼连接串；
3. **平台缺入口的应急回填**：先报告"该能力缺入口 = 缺陷"，脚本落 `temp/`、用完即删，
   交付说明里必须写明【走了例外 / 为什么 / 缺失的入口需另立需求补】，
   且**不得**据此宣称"功能已验证"或把数据当作已验收。

## 5. 验证标准（交付必须留下证据）

- **正向**：写清走过的真实入口（HTTP 方法 + 端点 + 认证身份，或 UI 路径，或 AS-BOT 工具名），
  并断言结果来自级联而非直写（如 publish 后核 `adh_ontology_objects` / 图谱节点 / KB 版本戳一致性）。
- **负向**：至少验证一次"应该被拒"的路径——无权限码 403、越界参数 400/422、孤儿引用硬阻断、未知 chart_type 告警。
  只跑通正例不算验证，护栏是否真在这条路上要靠负例证明。
- **可回滚**：必须手工清理时写清清理点并留半态检查（与原子切换同口径），不留"跑了一半"的库。
- **只读诊断不算产出**：探针/审计脚本可落 `temp/` 跑完即删，但不得用只读查询结果替代功能验证。

## 6. 自查清单（提交前逐条回答）

- 我这次产出的每一行业务/派生数据，是哪个产品入口写进来的？说得出端点/工具名/权限身份吗？
- 有没有哪个脚本自己拼了 `INSERT/UPDATE/DELETE` 直写业务表或派生表？
- 级联（对象→绑定→图→KB、发布→快照失效、权限→菜单下发）是产品跑出来的，还是我手动补齐的？
- 被绕过的权限码、校验、审计，有没有对应的负向验证？
- 若走了例外：原因与待补入口写进交付说明了吗？脚本在 `temp/` 且已删了吗？

## 7. 反模式速查

- ❌ `temp/` 下刷数脚本直写 `adh_ontology_objects` / `adh_metrics` / `adh_dimensions` / `adh_ontology_bindings` 造本体与字典；
- ❌ 直插看板 / 图表 / 数据集配置，绕过权限码、字段校验与快照失效；
- ❌ 用裸 SQL 造审计行或权限行，再从"页面能看到"推断"功能可用"；
- ❌ 脚本模拟 RLS/mask 结果写库，冒充脱敏链路已生效；
- ❌ "先刷数上线、接口以后补"——把缺陷延期，还让所有人以为功能已完成；
- ❌ 拿一次性脚本的退出码当验收结论（验收必须是产品路径 + 负向用例）。

## 8. 与相邻规则的关系

- `script-hygiene.md`：那条管"脚本放哪、活多久"，本条管"脚本能做什么"——② 类脚本只编排调用，不刷数；
- `no-silent-degradation.md`：刷数后"看起来能用"正是被禁止的假成功；
- `ontology-modeling.md` §1/§6：本体唯一可编辑源与级联一致性；
- `security-guardrails.md` §1/§9：取数唯一治理入口与审计不可旁路；
- `menu-permission-sync.md` §4：权限/菜单走幂等迁移并应用到库；
- `as-bot-system-waker.md` §2：AI 写动作只落草案、publish 独立把关。
冲突时以**更严**的一侧为准。
