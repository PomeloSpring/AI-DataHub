# UI 资源显示与选择规范：显示用 name，选择用选择框 — 强制规范

> 页面上的一切资源引用（数据源、用户、工作空间、同步任务、集成应用、策略、角色、看板等）对用户的呈现必须是可读的 name/label；交互录入必须从资源清单中选择，**不得要求或依赖用户手输内部 ID**（雪花 id/自增 id）。

## 1. 显示：name 为主，ID 仅次要
- 资源引用出现在列表单元格、卡片、详情、下拉值、表格列、日志上下文时，**必须显示 name/label**；禁止把裸 id 当作主要展示内容（反例：`ID:325991609814964`、`ds:5`、`0（全局）` 这类以数字充当名称）。
- id 仅允许作为次要信息出现在 `title` 属性、小字辅助行或调试详情中。
- 资源已被删除/不可见时显示明确的可读标注（如「数据源已删除」），**不得回退成裸 ID**；原 id 可放 `title` 供排查。
- id→name 映射来源必须是资源列表接口（如 `/datasources/`、`/users/`）或后端随对象返回的 name 字段；列表未加载时不编造名称，用「加载中/未知」占位。

## 2. 选择：用选择框，不手填 ID
- 一切"从既有资源集合中选一个/多个"的输入（表单录入、绑定关系、筛选条件）**必须使用选择框**（Select/下拉/可搜索选择），选项显示 name；禁止让用户手输资源 ID（反例：placeholder="输入用户ID"、"应用ID"、"任务 ID"）。
- 选择框选项来自资源清单接口；筛选场景提供「全部」空选项；选项按 name 排序或展示，value 仍可用 id（value 用 id 是实现细节，不违反本规范）。
- 仅两类例外允许自由输入：① 外部系统凭据标识（如第三方 App ID/知识库 ID，本系统无清单可枚举）；② 无清单可枚举的自由查询条件。例外处应注明原因。

## 3. 落地与自查
- 新增/修改 UI 时自查两条：凡 placeholder/标签出现"XXID"且指向本系统资源的，一律改选择框；凡渲染 `{xxx_id}` 当作名称的，一律改 name 映射。
- 后端返回给前端展示的资源对象应尽量携带 name 字段（列表 JOIN 或响应组装），避免前端拼 `ID:${id}` 兜底。
- 发现存量"裸显/手填 ID"视同缺陷，随手修复并在回归中覆盖（断言页面出现 name 而非裸 id）。
