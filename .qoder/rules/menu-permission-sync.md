# 页面调整与角色菜单配置同步 — 强制规范

> 页面/导航是给用户看的，角色权限里的「菜单与功能」是给管理员配的，**两者必须同一批改动对齐**。
> 页面加了入口却没登记菜单、改了名却留旧 label、挪了模块却留旧 section、菜单登记了却没挂权限点——
> 结果就是角色页出现"配了没用/该配的看不到"的空承诺，或存量用户入口凭空消失。菜单配置漂移视同缺陷，必须同批修复。

## 1. 触发面：什么改动必须同步
- 新增/删除/重命名/移动菜单项（含侧栏分组调整）、新增页面入口；
- 改默认落地页、入口显隐口径（如"恒可见"改"按权限码"或反之）；
- 权限点（perm_code）增删、改 label、换菜单归属（读/写权限拆分到不同菜单）；
- 以上任意一项发生，**同一批次**完成 §2 的登记与迁移，不得"先改页面、权限配置以后再说"。

## 2. 同批必须落地的五件事
1. **菜单登记** `adh_menu_registry`：`menu_key`（路由式命名，如 `workspace:dashboards`）+ `label`（与侧栏文案一致）+ `section`/`module`（与实际分组一致）+ `sort`（与侧栏顺序一致）+ `perm_code`（显隐反查用）+ `ai_access`；
2. **权限点归属** `adh_perm_registry.menu_key`：读权限归消费菜单、写权限归管理菜单（样板：`dashboard:read`→`workspace:dashboards`，`dashboard:manage`→`system:dashboards`）；一个菜单下至少要有一个权限点，否则角色页渲染不出该菜单（配了也白配）；
3. **存量角色默认授权**：新菜单对应的权限点要 `INSERT IGNORE` 给既有角色，维持迁移前的入口可见现状（管理员仍可按角色收回）；漏了这步 = 存量用户入口凭空消失；
4. **前端显隐口径对齐**：侧栏/入口按 `isMenuAllowed(toMenuKey(...))` 从权限码反查，与登记的 menu_key 一一对应；确需 `always: true` 例外（如资产清单=工作站基础功能）必须在代码注释写明原因；
5. **回归**：菜单显隐用例（`WorkspaceLayoutMenuFilter.test.tsx` 等）+ 角色权限页「菜单与功能」的菜单分组/名称/顺序与实际导航逐项一致。

## 3. 真值源与失效写法（防配错表）
- 菜单显隐的真值源 = **权限码反查**（`adh_menu_registry.perm_code` ⋈ `adh_role_perms`，由 `/roles/current/permissions` 下发 menus）；
- `adh_role_menus` 是遗留表，后端已不读取——**不要往那写**，写了等于没配；
- 禁止在前端硬编码"某菜单恒可见/恒隐藏"绕过登记（例外必须是显式产品决策并留注释），也禁止用第二套判断替代权限码反查。

## 4. 迁移落地纪律
- 登记/授权一律走幂等迁移 SQL（`INSERT ... ON DUPLICATE KEY UPDATE` / `INSERT IGNORE` + 从权限点回填 `menu_registry.perm_code`），文件进 `docker/mysql/*_migration.sql`，可重复执行；
- 迁移不止提交文件：**要应用到当前库**并核验（查 `adh_menu_registry`/`adh_perm_registry` 生效行、模拟目标角色的 menus 反查）；
- 排序/label/section 的调整写进同一迁移，避免"库里是旧结构、代码是新导航"的半截状态。

## 5. 自查清单（提交前逐条回答）
- 新入口在角色权限「菜单与功能」里能看到吗？名字/分组/顺序和侧栏一致吗？
- 勾选/取消该菜单真的会控制入口吗（不是死开关）？取消后旧角色还能进吗（默认授权是否漏配）？
- 迁移幂等可重跑吗？应用到库了吗？菜单显隐用例更新了吗？

## 6. 反模式速查
- ❌ 页面新增入口不登记菜单（功能有、配置无，角色页看不到）；
- ❌ 登记了菜单但 `perm_code` 为空/没挂权限点（角色页渲染不出，或勾选无效的死开关）；
- ❌ 只改前端 label/分组不改 `adh_menu_registry`（角色页显示旧名旧位置）；
- ❌ 新菜单漏了存量角色默认授权（老用户入口凭空消失）；
- ❌ 改了默认落地页/入口显隐口径却留旧口径代码与旧菜单结构（双口径并存）。
