The service is assembled in `main.py`, which mounts eight FastAPI routers (`chat`, `agent`, `knowledge`, `pipeline`, `query`, `history`, `playground`, `model-config`) under `/api/*` and pre-warms the agent registry on startup via `nl2sql.orchestrator.pipeline_orchestrator._init_agents`. The `services/` layer translates HTTP requests into calls against three backend subsystems: `nl2sql/` (intent classification → RAG metadata fetch → LLM SQL generation → validation/execution → multi-step workflow), `agent/` (configurable agent loop over MCP tools with an intent router), and `rag/` (BM25 + vector + Neo4j graph strategies). Cross-cutting concerns are shared through `config/`: YAML skill/system prompts per agent, reusable rule files (date handling, limits, null handling, SQL safety) consumed by both NL2SQL validators and agent system prompts, and an `agent_loader` that discovers agents from the same config tree. A parallel `mcp_server.py` exposes the same tool surface as an MCP server so agents can be invoked out-of-band. Startup/shutdown hooks centralize resource lifecycle (agent registry init, Langfuse flush).
