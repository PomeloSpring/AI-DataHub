The module is organized as a layered orchestration system with three parallel entry points under `orchestrator/`:
- `pipeline_orchestrator.py` is the single public entry (`execute_pipeline`) that classifies intent via `intent/intent_classifier.py` (fast regex path for chat/correction/explain) and dispatches to one of three pipelines: `quick_pipeline.quick_generate` (Intent→RAG→LLM→Validate→Execute), `deep_pipeline.deep_generate` (wraps the existing Loop Engine with RAG + result analysis), or `agent_pipeline.agent_generate` (full tool-augmented LLM agent with autonomous MCP/tool calling).
- `intent/` holds lightweight intent detection (`intent_classifier`, `query_rewriter`) used by both quick and deep paths.
- `sql/` provides reusable building blocks — `multi_step_planner` (pattern-based decomposition into sequential SQL steps), `query_executor` (pymysql-backed Doris/MySQL/ES execution with connection caching and audit logging), `sql_validator`, `semantic_validator`, `sensitive_detector`, `template_loader`, and `feasibility_checker`.
- `prompt/prompt_builder.py` centralizes prompt construction for NL2SQL, correction, chat, and M-Schema/ER diagram formatting consumed by all pipelines.
- `orchestrator/workflow/` implements a pluggable DAG engine (`dag_engine.DAGExecutor`) that loads workflow definitions from `adh_workflow_configs/steps/edges`, performs topological sorting, executes layers in parallel via `asyncio.gather`, and supports conditional branching; `loop_engine.py` drives the iterative metadata-supplement loop used by deep mode.
- The agent pipeline defines its own tool set (`SYSTEM_TOOLS`, `ORCHESTRATOR_TOOLS`) in `agent_pipeline.py` and delegates execution to `agent_tools.execute_system_tool`, which bridges tools to RAG, metadata DB, and query executor. Agents are lazily registered at first deep-mode request via `_init_agents`, loading built-in Data Analysis Agent plus configurable agents from `adh_agents`.
Dependency direction flows inward: orchestrators depend on intent → prompt → sql sub-packages; sql sub-packages depend only on shared services (DB, LLM client); no cross-imports between sibling sub-packages except via the orchestrator layer.
