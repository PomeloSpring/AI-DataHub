The service follows a thin API layer over a dedicated services layer. `main.py` bootstraps the FastAPI app, mounts CORS, registers four routers (`/api/dashboard`, `/api/charts`, `/api/reports`, `/api/component-data`), and exposes a `/health` probe. Each router in `api/` defines Pydantic request/response models and delegates all business logic to corresponding classes in `services/`: `DashboardService`, `ChartService`, `SnapshotService` live in `dashboard_service.py`; `ComponentService` lives in `component_service.py`; `report_service.py` handles report generation. The services layer owns all persistence against MySQL via `services.shared.common.db.metadata_db.get_metadata_conn()` and executes user-supplied SQL against configured datasources (MySQL or Elasticsearch) through `_execute_on_datasource`, which resolves connection details from `get_datasource_by_id`. Shared cross-cutting concerns — authentication (`get_current_user`, `get_workspace_id`), TTL-based dashboard cache (`dashboard_cache`), and SQL validation (`validate_sql` from `datamind.nl2sql.sql.query_executor`) — are imported from `services/shared/common`. Deployment is containerized via `Dockerfile` (Python 3.11-slim, installs shared + dataviz requirements, sets `SERVICE_PORT=8004`) and can be started locally via the shared `start.sh` script that discovers the module string `services.dataviz.main:app` and port 8004.
