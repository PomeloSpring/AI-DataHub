The root layer provides two complementary runtime orchestration paths. For local development, `start-all.sh` / `stop-all.sh` / `restart-all.sh` launch each Python service as a background uvicorn process under a shared `PYTHONPATH`, writing PIDs to `pids/` and logs to `logs/`; the service registry is declared once in the script's `SERVICES` array (authservice, datacatalog, datagov, dataviz, datamind, dataflow, aiplatform, vectorservice, graphservice) plus the Vite frontend on port 3000. For containerized deployment, `docker-compose.yml` defines a `backend` service (built from the root `Dockerfile`) and a `frontend` service that depends on it via a healthcheck, sharing a `chatbi` bridge network and an `embedding-cache` volume. The root `Dockerfile` installs shared requirements from `services/shared/common/requirements.txt` and exposes ports 8001–8011 for all backend services. Cross-cutting infrastructure lives in `docker_infra/` (MySQL, Neo4j, SQLite, Doris schemas) consumed by every service, while `shared_libs/` supplies common models, migrations, and the graph/vector services reused by multiple microservices. Environment variables are centralized through `.env.example` and sourced via `services/.env` at startup.
