The service follows a thin API layer over a business-logic layer. `main.py` bootstraps a FastAPI app on port 8006, registers CORS, mounts five routers under `/api/{auth|users|workspaces|roles|audit}`, and exposes a `/health` probe. Each router in `api/` is a small FastAPI `APIRouter` that validates Pydantic request models and delegates to functions in `services/auth_service.py` (authentication, user CRUD, password handling, audit) and `services/rbac_service.py` (role/permission CRUD and permission checks). The services layer owns all SQL via parameterized queries through the shared `services.shared.common.db.DBConnection` pool; sensitive fields (`email`, `phone`) are encrypted/decrypted using AES-256-GCM helpers from `services.shared.common.crypto`, while passwords are bcrypt-hashed. Tokens are HS256-signed JWTs created/decoded via `PyJWT` with secrets from `services.shared.common.config`. Dependency direction is strictly `api → services → shared.common`; there are no cross-imports between sibling api modules.
