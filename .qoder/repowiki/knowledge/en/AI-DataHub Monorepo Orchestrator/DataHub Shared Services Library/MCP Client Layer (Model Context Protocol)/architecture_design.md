Three-layer design inside the package:
- `client.py` defines `MCPClient`, a per-server async connection wrapper around the `mcp` SDK that supports three transports (`sse`, `streamable_http`, `stdio`) selected by transport name in `connect()`. Each transport is imported lazily inside its handler to avoid hard dependencies, and tool discovery is performed via `session.list_tools()` after `initialize()`.
- `registry.py` defines `MCPServerConfig` (dataclass) and `MCPRegistry`, which loads server definitions from the `adh_mcp_servers` table via `services.shared.common.db.get_metadata_conn`, caches them with a 60s TTL, applies a `tools_config` whitelist against `discovered_tools`, and exposes `get_client()` / `call_tool()` that create fresh connections per call. A module-level singleton `_registry` is exposed via `get_mcp_registry()`.
- `tools.py` provides `MCPToolCaller`, a high-level facade that delegates to the registry and formats tool schemas for Anthropic's `tool_use` API via `convert_tools_for_anthropic`; it also offers prompt-friendly listing helpers.
Dependency direction is one-way: `tools` → `registry` → `client` → `mcp` SDK; the package re-exports `MCPRegistry`, `MCPServerConfig`, `MCPClient`, `MCPToolCaller` from `__init__.py`. A key architectural constraint (documented in comments) is that anyio cancel scopes are task-bound, so no connection caching across tasks — every call creates and tears down a fresh client within the same async task.
