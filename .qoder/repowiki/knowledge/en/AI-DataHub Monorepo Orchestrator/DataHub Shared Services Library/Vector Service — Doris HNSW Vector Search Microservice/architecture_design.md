The module is a standalone FastAPI application (`main.py`) that mounts an API router under `/api/vector` and exposes a `/health` endpoint. It runs two servers from the same process: the main Uvicorn server on port 8010 (REST) and a child subprocess running `mcp_server.py` on port 31010 serving an MCP SSE transport built on Starlette. The `vector_db.py` layer provides a lazy-initialized, global `PooledDB` connection pool backed by `pymysql`, configured via shared config keys (`VECTOR_DB_*`), and exposes a context-manager-based `get_vector_connection()` used by both the REST handlers and the MCP tool handlers. The `api/vector.py` router defines Pydantic request/response models and implements five endpoints: POST `/search` (L2 distance approximate nearest neighbor via `l2_distance_approximate`), POST `/upsert`, POST `/upsert-batch`, DELETE `/{table}/{id_column}/{id_value}`, and GET `/tables` (discovers tables with an `embedding` column). The MCP side (`mcp_server.py`) declares two tools (`search_vector`, `upsert_vector`) with JSON schemas and handles them by reusing the same SQL patterns and connection pool. Dependency direction is one-way: `main.py` → `api/vector.py` + `mcp_server.py` → `vector_db.py` → `services.shared.common.config`; there is no reverse dependency. Lifecycle management uses FastAPI's `asynccontextmanager` lifespan to initialize and close the pool, and the entry point spawns/terminates the MCP subprocess in its `finally` block.
