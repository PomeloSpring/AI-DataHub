The module is a standalone FastAPI application (`main.py`) that mounts a single router under `/api/graph` (with a `/api/health` probe). It layers three concerns:
- `api/graph.py` — a low-level Cypher-exposing REST layer that directly opens a lazy-initialized `neo4j.GraphDatabase` driver per request for ad-hoc queries, node listing, neighbor traversal, shortest-path, and stats.
- `graph_service.py` — the domain `GraphService` class wrapping `AsyncNeo4jStore` / `Neo4jStore`, `GraphBuilder`, and `GraphRetriever` from `services.datamind.rag.graph_rag`; it implements typed graph queries for three graph types (`TABLE_RELATION`, `BUSINESS_KNOWLEDGE`, `DATA_LINEAGE`) with fallback queries and in-process search/filtering, plus node/relation CRUD and metadata sync via `sync_from_metadata`.
- `graph_sync_service.py` — an event-driven sync engine (`GraphSyncService`) that dispatches `SyncEventType` events (table/column/term/metric/dimension create/update/delete plus `FULL_SYNC`) to dedicated `_sync_*` handlers which mutate Neo4j nodes and relationships; it exposes a process-wide singleton via `get_graph_sync_service()` and uses `asyncio.create_task` for fire-and-forget processing.
Dependency direction: `main.py` → `api/graph.py` (direct Neo4j driver) and `graph_service.py` (high-level service); `graph_service.py` depends on shared RAG graph components; `graph_sync_service.py` lazily imports `Neo4jStore` and the metadata DB connector only when handling events. The app runs inside a container built from `Dockerfile` exposing port 8011, with `start.sh`/`stop.sh` as entry scripts.
