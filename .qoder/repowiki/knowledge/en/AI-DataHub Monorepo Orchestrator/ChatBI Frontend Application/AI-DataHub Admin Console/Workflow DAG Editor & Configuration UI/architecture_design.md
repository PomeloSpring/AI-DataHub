The module is built around a React Flow (`@xyflow/react`) canvas with a Zustand store as the single source of truth. `WorkflowEditor.tsx` is the top-level route component that wraps content in `ReactFlowProvider`, renders a left sidebar (workflow list + `NodePalette`), the central `DAGCanvas`, and an optional right-side `NodeConfigPanel`. The `store.ts` Zustand slice owns `workflows`, `currentWorkflowId`, `nodes`, `edges`, `selectedNode`, `isDirty`, `isLoading` and exposes CRUD actions (`loadWorkflows`, `loadWorkflow`, `saveWorkflow`, `createWorkflow`, `deleteWorkflow`) plus node/edge mutation helpers; it serializes the graph to the backend via `/admin/workflows` REST endpoints and auto-generates linear edges when none are stored. `DAGCanvas.tsx` maps each `NodeType` to a custom node component under `nodes/` (`StartNode`, `EndNode`, `StepNode`, `ConditionNode`, `ParallelNode`, `MergeNode`; `agent` and `mcp_tool` reuse `StepNode`). `types.ts` centralises all shared types (`WorkflowNode`, `WorkflowEdge`, `WorkflowConfig`, `NodeTypeInfo`) and declares the canonical `NODE_TYPE_DEFINITIONS` and `STEP_TYPE_OPTIONS` arrays that drive both the palette and config panel. `WorkflowConfig.tsx` is a separate read-only documentation page describing quick/deep/agent modes and retrieval strategies — it has no runtime dependency on the editor state.
