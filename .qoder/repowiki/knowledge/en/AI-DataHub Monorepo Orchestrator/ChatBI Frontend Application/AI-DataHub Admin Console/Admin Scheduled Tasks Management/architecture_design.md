Three co-located React page components under `frontend/src/pages/admin/` form a self-contained admin feature:
- `ScheduledTasks.tsx` is the root list view: fetches paginated tasks via `listScheduledTasks`, renders a table with inline toggle/trigger/delete actions, opens a create/edit dialog wrapping `ScheduledTaskForm`, and conditionally swaps to `ScheduledTaskLogs` when a log view is selected.
- `ScheduledTaskForm.tsx` is a stateful form component that loads dropdown data (notification channels, report templates, datasources, MCP servers, agents) on mount, supports both single-value and multi-value task_config fields for backward compatibility, validates per-task-type inputs (SQL vs Agent questions), and calls `createScheduledTask` / `updateScheduledTask` from `@/api/scheduledTask`.
- `ScheduledTaskLogs.tsx` is a detail sub-view receiving a `taskId` prop; it fetches logs (`listScheduledLogs`) and stats (`getScheduledTaskStats`), provides status filtering, pagination, and in-dialog actions to cancel/marking success/failure/timeout via `updateLogStatus`, plus bulk cleanup of old or stale logs.
All three components depend only on shared UI primitives from `@/components/ui/*`, the `sonner` toast library, and the `@/api/scheduledTask` client — no cross-component state sharing beyond parent-driven props/dialogs. The module has no internal routing; navigation between list and logs is driven by local state (`logsTaskId`).
