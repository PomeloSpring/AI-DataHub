The module is split into two build targets under `frontend/`: the main SPA (`src/`) built by Vite and served via nginx, and an independent Web Component SDK (`sdk/`) built to a UMD bundle for third-party embedding. The SPA entry (`main.tsx` → `App.tsx`) wires three top-level layouts — `WorkspaceLayout`, `DataPlatformLayout`, and `SystemLayout` — each guarding routes with a `PrivateRoute` that checks `authStore.token`. All pages and components consume shared Zustand stores (`authStore`, `workspaceStore`, `dashboardStore`, `chatStore`, `aiAssistantStore`, etc.) and call backend APIs through a single Axios client in `src/api/client.ts` plus feature-scoped modules (`governance.ts`, `lineage.ts`, `metrics.ts`, `quality.ts`, `sync.ts`, `tags.ts`, `scheduledTask.ts`, `workspace.ts`). Domain sub-modules (admin, dashboard editor, knowledge graph, catalog, AI assistant) are page/component trees mounted under these routes; they do not import each other directly but communicate through the shared stores and API layer. The SDK lives outside the SPA, ships as `@chatbi/sdk`, and exposes `chatbi-chat` / `chatbi-dashboard` web components that independently connect to the same backend endpoints.
