The service is organized in a two-layer layout under `services/datacatalog/`:
- `api/` contains FastAPI `APIRouter` modules (catalog, metadata, templates, glossary, lineage, metrics, tags, datasources, menu, admin_compat) that define HTTP routes and delegate all business logic to the sibling `services/` layer.
- `services/` holds pure Python modules (`catalog_service`, `datasource_service`, `menu_service`, `metadata_service`, `metrics_service`, `relation_service`, `tags_service`, `template_service`, `term_service`) that perform database operations via `...shared.common.db.DBConnection` against the shared DataHub schema tables (`adh_table_info`, `adh_column_metadata`, `adh_metrics`, `adh_business_terms`, etc.).
- `main.py` is the FastAPI application entry point: it instantiates the app, registers CORS, mounts each router under its `/api/*` prefix, and exposes a `/health` endpoint; it runs on port 8005 via uvicorn.
- `mcp_server.py` defines an alternate transport: it builds an MCP server using `..shared.common.mcp_base.create_mcp_server` and exposes tools (`search_metadata`, `get_table_schema`, `get_metrics`, `query_tags`) backed by the same services, with `create_mcp_app()` producing a Starlette app served at `/sse` and `/messages`.
- Dependency direction is strictly one-way: `api → services → shared.common.db`; no cross-imports between sibling services exist.
- Lifecycle is managed by the shared `start.sh` script which detects this module as `datacatalog`, launches `uvicorn services.datacatalog.main:app` on port 8005, and writes PID/log files into the project root `pids/` and `logs/` directories.
