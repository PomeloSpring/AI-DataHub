# 大屏布局与栅格

> 本篇是**几何推导与维护口径**（给改服务端版面算法的人看）。对模型的行为口径以 `SKILL.md`
> 的「概念 / 属性 / 规则」为准：间距 = 板级 `gap`，大小与位置 = `layout`/`layout_rows`/`size`/`after`，
> **不要**用手写 `position` 去凑等距。

工具侧画布基准 **1920 × 1080**。未给 `layout`/`position` 时按下列规则自动布局
（2026-11-19 整改：出主次 + 顶部留白；上一版是"≥3 张一律 2~3 列等分等高"，用户反馈"全是一样的大小和排布"）：

| 场景 | 自动布局规则 |
|------|--------------|
| **多站一屏**（widget 出现 ≥2 个不同 `site`） | **站点矩阵**：列 = 站点（列宽 = 1920/站点数），行 = 指标家族（KPI / 趋势 / 其他）；同族等高、同站同列，缺格留空不拉伸。站点顺序 = 用户给出的顺序；异构卡（饼图/表格等「其他」族）未铺满全部站点时整行均分并居中。**跨站对比本来就该等大**，该模式忽略 `emphasis` |
| 单站/无站 | **带（band）分层，不再等分**：顶部留白 32 → KPI 一行（`h=180`，单卡最宽 480，左对齐）→ **首带主图**（左 2/3 一张趋势 hero + 右列 1~2 张辅图上下堆叠）→ 其余带每行 2~4 张，明细/表格落整宽带 |

单站分层的真实约束（`_layout_stacked` / `_plan_content_bands` 逐条守住，渲染层不兜）：

- **内容区从 `y=32` 起排**：内容贴上边缘会和播放页标题栏挤在一起（用户反馈"顶部要留一些空隙"）；
- **`h ≤ 600`**：前端把自动带高**截顶**到 600px，写更高等于白留；
- **`h ≥` 类型最小高**：表格 `360` / 其他 `280` / KPI `128`——抬高压破下一带就是"卡片一张比一张靠右下"的斜阶梯；
- 带高在剩余空间里**分配**（不是固定值）：放不下时先放宽每行张数（4→6→8），**还放不下就显式拒绝并建议拆板**，不做静默挤压；
- **内容图 >12 张显式拒**（1920×1080 内排不出主次），总图数上限仍是 24（含 KPI 行）；
- **一切尺寸取 4px 倍数**（前端 `PAGE_ROW=4` 行格，`_snap4`/`_tile` 负责），主图宽取 **2/3 屏**；
  卡间**横向**空白只由板级 `gap` 决定（默认 16px，见下节等距数学）——在坐标里再"留 12px"就是记第二套账，
  渲染端按列取整时会把空白算歪；
- hero 归属由 `emphasis={hero, detail}` 按**图表标题**指定；未指定时按 趋势 > 占比 > 地图 > 表格 自动选，标题解析不到会回候选清单。

要点：

- **KPI 单卡宽度上限 480**：一张 KPI 拉满整屏会让迷你趋势被拉平、大数字悬在中间（历史观感缺陷）。
- **同族同排**：趋势族不跟饼图/表格/地图混行；混行会让观众以为是同一量级对比。
- **异构卡不进对比矩阵**：状态构成/表格/地图只在部分站点有时，不按站点列摆（会留出右侧一大片空白），改用整行均分居中（单张最宽 2/3 屏）；只有每站都有的同族图才是对比项。
- 未写 `site` 的图（跨站屏里漏标）落到**底部整行**，不静默丢图；建后核对 `layout` 看是否落到了底行。
- 总图数上限 **24**；5 站 × 3 指标 = 15 是常见规模，超过 24 才拆板。

## 等距数学与 gap 恒等式（2026-11-20 落地口径）

渲染端（`frontend/src/lib/dashboardPageLayout.ts`）把像素换算成**断点列**再排，Python 侧镜像同一套常量
（`screen_tools._BP_COLUMNS/_BP_WIDTHS/_DEFAULT_PAGE_GAP`，由 `tests/test_page_layout_constants_sync.py` 锁住不漂移）：

| 断点 | 列数 | 基准画布宽 | 默认 gap |
|------|------|-----------|----------|
| `screen`（大屏播放） | **64** | 1920 | 16 |
| `desktop` | 48 | 1440 | 16 |
| `tablet` | 24 | 768 | 16 |
| `mobile` | 1 | 390 | 12 |

- **gap 是板级属性**，存 `filters.design.page.gap`，四档各自取值；CSS 侧 `columnGap = gap`、**`rowGap = 0`**，
  纵向空白由 `gapRows(gap) = ceil(gap / PAGE_ROW) × 4` 个行格统一产生。
  → **手写的纵向像素间隙一律不生效**；要"行距"就改 `gap`（gap=20 → 纵向 20px，横纵相等）。
  → gap 建议取 **4 的倍数**，否则被抬到 4 倍数后横纵不等（横向 18、纵向 20）。
- **等距的充要条件 = 同带相邻卡列区间首尾相接**（`x₂ === x₁ + w₁`）。列取整是**左右边缘各自 round**，
  所以"看着均匀"的像素节距反而最危险：历史事故板节距 380px = 380×64/1920 = **12.67 列**，
  取整后列区间之间留下 1 列空洞 → 视觉间距在 **16px 与 46px 之间交替**（用户说的"间距不一样"就是这个）。
- **编译口为什么不会花**：`_col_bounds` 先算 0..64 共 65 个**共享列边界**像素（`round(k × W / 64)`），
  相邻卡取同一条边界值 → 相接是**构造出来的**，不是靠调坐标调出来的；每带列合计强制 = 64（余量归最右卡）。
- **判据**：`layout_audit.spacing.uneven_gaps` 列出"有空洞/重叠的卡对"，`even_spacing` 是布尔总结。
  只有 `even_spacing == true` 才可以向用户说"间距一致"。历史板大量 uneven，所以 `ok` 仍为 true
  （不刷屏），等距与否一律看 `even_spacing`。
- 语义词 → 列数：`full=64 / two_thirds=43 / half=32 / third=21 / quarter=16 / fifth=13`，或 `cols:8~64` 逐列直给。
  同行合计 > 64 且是**同一个等分词的舍入溢出**（五个 fifth = 65）→ 按 64 精确等分并在 notes 说明；
  不同词相加超宽（half + two_thirds）→ **显式拒**，让用户决定谁让位。

## 两套版面几何(易错点,务必区分)

同一个看板对象有两套版面口径,`position` 只驱动其中一套:

| 视图 | 几何 | 谁写 |
|------|------|------|
| 大屏播放 `/screen/<id>` | 走 `ResponsiveDashboardCanvas` → **响应式列格** | 由 `position` 像素**等比换算**得出(`automatic` 项),按断点重排 |
| 看板页面/编辑器 | pageLayout v3:按断点存**列格**（大屏 64 / 桌面 48 / 平板 24 列, 行单位 **4px**） | 前端编辑器「页面布局」保存,本工具**不写** |

推论(均为实测踩过的坑):

- `position` 的 `w/h` **只保证相对比例**,不保证像素级所见即所得;窄屏/平板会换列数重排,别向用户承诺像素还原。
- **`config.pageLayout` 是人侧编辑器私有物**：渲染端优先用它 → 本工具写的 gap/版面**不会生效**（会把该断点钉死，
  还会覆盖人的保存）。所以语义通道**从不写** `config.pageLayout`；检测到板内有钉死的卡时，`gap`/`layout_rows`/`size`
  一律**拒绝并指路**（进编辑器，或由用户先解除钉死），绝不假装改成功。
- **重叠的坐标会被渲染器"避让"成斜阶梯**:响应式画布对横叠的两张卡不报错,而是把后来者整体下移一行——
  肉眼看到的是"卡片一张比一张靠右下、右侧一大片空白"。所以坐标**绝不能横叠**,宁可排紧一点。
  服务端返回的 `layout_audit` 就是给这件事用的: `ok=false` 时按其 `overlaps` 指名重排,不要"先交付再说"。
- 控件类(`widget_*`)在页面视图按**自然尺寸**生成,不按 position 等比放大;图表才按等比映射。
- 列宽换算必须**把 gap 算进去**(只按列数等分不含间距会让控件/卡片窄一截,历史缺陷:日期区间控件"只显一半")；
  但**卡片之间的空白本身**仍只由 `gap` 决定 —— 编译口算的是 `span × columnPx − gap`，不是"再留几个像素"。
- **AI 侧现在能读能写的版面项**：四档 `gap`（间距）、每卡 `size`（占列）、`band`/`in_row`/`after`（位置）、
  整板 `layout_rows`（重排）。仍然只能在编辑器做的：逐列精确对齐（`pageLayout` 列格）、控件行、断点差异化的版面。

## 常见版式

- **多站对比一屏**（首选，用户要「一个屏看所有站」时）:列 = 站点、行 = 指标。每站一列：顶部 KPI（今年累计/同比）→ 中部趋势（月度走势）→ 底部构成（状态/类型占比）。5 站 = 5 列，每列 384px 宽；图数 5×3=15。
- **经营驾驶舱**:顶部 4 个 KPI 卡(y=32,h=180)→ 首带主趋势占左 2/3 + 右列两张辅图 → 底部整宽明细表。用 `layout_kpi_top`。
- **实时监控**:九宫格 `layout_grid_3x3`,每格一个 gauge/迷你趋势。
- **焦点分析**:左主右辅 `layout_left_right`,左侧大趋势/地图,右侧排行/KPI 列表。

> 不要为「每站一块板」而分身：除非用户明确要求分屏，多站永远先按上面的「多站对比一屏」排。

## 建后版面自检（对着 `layout` + `layout_audit` 逐条看）

`create_data_screen` / `update_data_screen` / `update_data_screen_chart` 的返回里都带 **`layout_audit`**（软件可核验,不靠"看着对"）:

- `ok` 必须为 `true` 再交付；为 `false` 时 `overlaps` 会指名哪两张压住了、`out_of_canvas` 列出越出 1920×1080 的图、
  `squeezed` 列出**低于前端最小高**的图（渲染层会把它们抬高 → 斜阶梯），先改坐标（或干脆省略 `position`、传 `relayout` 让服务端重排）再重新提交。
- **`hierarchy=false` = 版面没有主次**（内容卡全等宽等高，正是"一排一样大"的反馈）：减少图表，或用
  `emphasis={hero}` 指定主图后 `relayout=true` 重排；**不得**带着 `hierarchy=false` 交付。
- `over_tall` 非空 = 有卡 `h>600`，前端会截顶（写了等于没写），把带高压回 600 以内。
- `idle_rows` 是**整行未被占用的宽度**（如半屏卡旁边空 960px），只作观感参考：单张异构卡居中属于预期留白。
- **`gap`（四档生效值）+ `spacing.uneven_gaps` + `even_spacing`** 是间距这件事的唯一判据：
  `even_spacing=true` 才能说"间距一致"；false 时 `uneven_gaps` 指名了是哪两张卡之间有列空洞 ——
  修法是给这一带传 `layout`/`layout_rows` 重排（共享边界），或调 `gap`，**不是**微调某张卡的宽度数字。

人工再看四条:

1. KPI 是否在同一行、有没有被拉成整屏宽（`w` 应≈1920/KPI 数且 ≤480，不是 1920）；
2. 站点列有没有串列（每列应是同一站点，列宽相等）；
3. 同族图是否同排（趋势不跟饼图混行）、首带主图是否明显大于辅图；
4. 图数 ≤24；**单站分层另受"内容图 ≤12"限制**（超了会被显式拒并建议拆板），跨站矩阵按站点列排（5 站 × 4 指标 = 20 属正常规模）。

## 信息层级

- 最重要指标放左上与顶部;观众视线从左上看起。
- 同类图放同一行/列;卡间空白交给板级 `gap`(默认 16px),不要在坐标里另留;避免同一屏混用超过 2 种图表家族。
- 标题栏 `frame_title_bar` 放整屏标题与时间;角标框 `frame_tech_corner` 强化科技感。

## 图表选型(与渲染器一致)

趋势→`line/area/timeseries_line`;对比→`bar`;占比→`pie/rose/treemap`;多维→`radar`;转化→`funnel`;达成→`gauge`;排行/明细→`table/table_value`;核心数字→`big_number_trend/text_display`;地理→`china_map/world_map`。
