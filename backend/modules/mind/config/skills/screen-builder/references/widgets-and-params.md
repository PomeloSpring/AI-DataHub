# 参数控件（widget_*）与看板参数

> 一句话：**参数控件是"看板参数"的输入口，不是图表**。它本身不取数，值经看板参数翻译成
> 各数据集的 `${变量}` 才生效。**直建通道（`create_data_screen`）不产控件**——本文件告诉你
> 控件怎么工作、为什么直建里挂不上、以及用户要"能筛选"时该怎么回。

## 1. 控件清单（类型名必须逐字用这些，不存在 `widget_input` / `widget_button`）

| 类型 | 界面形态 | 关键 config | 绑定口径 |
|------|----------|-------------|----------|
| `widget_select` | 下拉选择框 | `options: [{label, value}]`、`paramKey` | `bind_param` = 一个逻辑参数名 |
| `widget_multi_select` | 多选下拉框 | 同上（值为数组） | `bind_param` = 一个逻辑参数名（多值） |
| `widget_date` | 日期选择器 | `paramKey` | `bind_param` = 一个逻辑参数名 |
| `widget_daterange` | 日期范围（起止） | `paramKey` | `bind_param` = `"start_key,end_key"`（逗号分隔，两个逻辑参数） |
| `widget_text` | 文本输入框 | `placeholder`、`paramKey` | `bind_param` = 一个逻辑参数名 |
| `widget_number` | 数字输入框 | 同上 | 同上 |
| `widget_label` | 静态文本标签 | `content`（无绑定概念） | 不参与参数 |
| `widget_search` | 查询按钮 | `label` | 触发整板重查询（`refreshCharts`） |
| `widget_reset` | 重置按钮 | `label` | 恢复参默认值后重查（与顶栏「重置」同口径） |
| `widget_export` | 导出按钮 | `targetChartId`（**必须显式指定**导出哪张图） | 无目标即报错，不回退"第一个图" |
| `widget_decision` | 决策建议卡 | `treeKey`、`paramBindings` | 服务端算好结论，展示型 |

通用外观键（`config`）：`label`、`showLabel`、`labelPosition`（left/top）、`defaultValue`、
`placeholder`、`widgetStyle{...}`。控件尺寸按**自然尺寸**给（页面视图不随 position 等比放大），
同一排控件要等高对齐；精确像素版面只能在编辑器「页面布局」里保存。

## 2. 控件 → 取数的消费链路（三层，缺一层就是"填了不出数"）

```
控件 config.paramKey / bind_param   →   看板参数（page_params / 参值）
        →  刷新时下发 params:{...}   →   数据集入参变量（adh_datasets.variables）
        →  正文 ${变量} 渲染          →  取数
```

- **`paramKey`**：控件对应看板上的**逻辑参数**（业务名/键），用于同名控件与参数栏对齐；
- **`bind_param`**：真正写页面参数值的键（日期区间必须写成 `start,end` 两个键）；
- **数据集 `variables` 是唯一口径权威**：声明了哪些入参、什么类型、正文怎么用；
  声明里的 `dash_key` 是人工归一的位置（控件键与数据集变量名不同名时靠它对齐；不写则按正文形状推断）；
- 规范逻辑参数名 `time_window`：时间窗口（区间 + 可选的相对天数回退）统一进这个键；
- **未被任一数据集接住的参数会回传 `unbound_params`**，图卡上显式标注"参数未生效"——
  那是**控件挂错了/数据集没声明**，不是"没数据"。绝不静默按默认值出数。

## 3. 为什么直建通道不产控件（`create_data_screen` 会直接拒收）

- 每张图的口径在建屏时**固化进数据集**（`chart_preset.intent`），刷新时按这份固定意图取数；
  不会去读控件绑定的变量 → 控件写了值也没人消费，属"能填不出数"的死控件。
- 因此工具对 `filters`（交互筛选参数）**显式拒绝**，可建类型清单里也**没有 `widget_*`**。
  这不是遗漏，是口径边界：不生成"看着能筛选、其实筛不动"的空控件。

## 4. 用户要"能筛选/能切换"时怎么回

如实说明直建通道的限制，然后给**能落地**的三条路（让用户选，不要自行绕）：

1. **数据集参数化 + 人工挂控件（标准路径）**：到「数据集」页把正文里要筛的谓词改成 `${变量}`
   外置（并在入参声明里登记类型），再在「看板编辑器」拖 `widget_select` / `widget_daterange`
   绑定该变量；之后点查询按钮/刷新即按新值取数。
2. **多版本固定口径图**：用户只是要"分站点/分类型各看一份"时，直接多建几张固定口径的图
   （或按站点列一屏排开），比控件更省事且口径可核。
3. **相对时间窗**：要"最近 7 天/本月/今年"这类，用意图里的 `time_window`（每次刷新按当前时刻重算），
   不要造日期控件、也不要把绝对日期写死。

## 5. 反模式（发现即停）

- ❌ 传 `widget_*` 给 `create_data_screen` / `update_data_screen_chart`，或传 `filters` 想"顺便带个筛选"；
- ❌ 用 `widget_input` / `widget_button` 这类**不存在的类型名**（渲染器没有分支，挂上去就是空白）；
- ❌ 控件不写 `paramKey`/`bind_param`：看着是个输入框，填了什么都不发生；
- ❌ 把控件当数据源（控件 `chart_type` 不取数，`data_audit` 里的行数对它无意义）；
- ❌ 导出按钮不指定 `targetChartId`，或承诺"会导出全部图"；
- ❌ 向用户承诺控件"改完立刻全屏联动"——联动范围取决于各数据集是否声明了同一个逻辑参数，
  没声明的图不会被筛（属预期，不算 bug，但要提前说清）；
- ❌ 用控件值去"切换数据源/站点库"：选源是权限与站点拓扑的裁决，不由控件值触发。

## 6. 挂完控件的自检（人工/编辑器场景）

1. 控件有值后点查询/刷新，**目标图的行数或数值确实变了**（没变 = 参数没被接住）；
2. 图卡上没有"参数未生效（`unbound`）"标记；有就回去核数据集 `variables` 声明与控件键；
3. 日期区间两端都写对了（`bind_param` 两个键，缺一端等于半区间）；
4. 重置按钮能把控件与图一起恢复默认（只清一侧 = 空承诺）。
