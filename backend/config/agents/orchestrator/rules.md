# 调度规则（必须遵守）

## 数据源约束

- **数据查询 Agent（data_analysis_agent）**：必须选数据源才能调用
- **日志分析 Agent（log_analysis）**：不需要选数据源，通过 MCP 服务访问 ES
- **其他 Agent**：查看 agent graph 中的数据源类型，匹配才能调用
- 如果当前数据源没有匹配的子 Agent，**必须通过 ask_user 确认**

## 调用子 Agent 的 question 参数组装

### 通用逻辑

1. 从子 Agent 的**入参要求**（agent graph 中列出）确定必须包含哪些信息
2. 从**用户原话 + 对话历史**中提取这些信息
3. 按子 Agent 要求的**格式**列出关键信息（如 `Index: xxx`）
4. 再附上**用户原话**（不改写含义）
5. **缺少必须信息 → ask_user 确认**，不要猜测

### 核心原则

- **保留用户原意**，不能增加、删除、改变用户表达的含义
- **按子 Agent 的入参要求格式化**，确保子 Agent 能解析
- **不确定时 ask_user**，这是最重要的规则

## 工具直接调用规则（混合模式）

### 优先委托子 Agent
- 常规任务（数据查询、日志分析等）→ 优先调用子 Agent
- 子 Agent 有领域专长，处理更专业

### 可直接调用 MCP 工具的场景
1. **子 Agent 失败后兜底**：子 Agent 调用工具失败，错误是 retryable 的 → 直接重试该工具
2. **无匹配子 Agent**：当前数据源没有匹配的子 Agent，但有对应 MCP 工具 → 直接调用
3. **简单信息获取**：仅需获取元数据或简单信息，无需子 Agent 完整流程

### 禁止行为
- 禁止改写用户原话的含义
- 禁止省略用户提到的关键信息
- 禁止绕过子 Agent 直接执行复杂查询（SQL 生成 + 执行 + 分析的完整流程）
- 禁止在有匹配子 Agent 时跳过子 Agent 直接调用工具
- 禁止对 retryable=false 的结果重试
- 禁止在回复中包含程序报错信息
- **不懂就问用户，不要乱猜**

## 结果处理

- 子 Agent 返回成功 → 使用其结果回答用户
- 子 Agent 返回失败且 retryable=false → 告知用户失败原因
- 子 Agent 返回失败且 retryable=true → 补充上下文后再调用一次，或直接调用工具兜底
- 所有子 Agent 都无法处理 → 尝试直接调用 MCP 工具兜底
- MCP 工具也失败 → 告知用户
